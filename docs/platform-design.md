# Post-Event Report Platform: Design

This document describes how to build the internal **Post-Event Report** module in the ETB2B events portal. For every BrandEquity IP event (starting with BWS), it assembles event data automatically, shows it to the events team with drill-downs and quality checks, and generates the sponsor PPT by **T+1**.

Related documents:
- `ip-deck-automation-spec.md`: the 16 sections, their data points and output format
- `bws-2025-deck-retention-gaps.md`: why the current deck fails
- `retention-root-causes.md`

## 1. Design principles

1. **Build inside the existing events portal, not beside it.** Registrations, attendees, wishlist users, speakers, agenda, sponsors, Design templates and the Media Center already live there, under the same event ID and login. A new sidebar module next to *Activity & Reporting* avoids a second system.
2. **One metric definition feeds both the page and the PPT.** Every number is computed once, with its formula, base (n), source and "as of" time. This makes 7.18x vs 17.8x-style conflicts impossible.
3. **Capture data at the source, on the day.** T+1 is only possible if check-in, media uploads and post URLs are recorded during the event. The platform enforces this with a readiness checklist rather than chasing people afterwards.
4. **AI drafts; people approve.** AI does classification, transcription, quote picking, photo picks and captions. Numbers are never generated by AI. Anything customer-facing that AI produced needs one human approval.
5. **The export contains only totals.** Attendee-level data stays in the portal; the PPT never carries names or emails.
6. **Works with manual uploads first, APIs later.** Every external source has a CSV/upload fallback in the format teams already produce, so phase 1 doesn't wait on integrations.

## 3. Core components

### 3.1 Data domains (what gets ingested)

| Domain | Source | Connector (phase 1 → later) | Owner | Must be captured by |
|---|---|---|---|---|
| **Event & design** | Event Details; Design → Template / Top Banner; Key Discussion Points | Direct DB/API read | Content | T-7 |
| **Targets (promises)** | **New "Event Targets" form**: attendees, CXOs, speakers, sessions, impressions, plus indicative-speaker list | New form in portal | Sales / Editorial | Before the event is announced |
| **Attendees** | Registrations, Shortlisted, **Attendees (check-in)**, form type, lead / visitor / conversion source | Direct read | Delegate acquisition / Ops | Check-in live on T0 |
| **Speakers & agenda** | Speakers (group, weightage, status), Agenda sessions | Direct read + **new session fields**: owner type (ET / brand / partner), format, theme, partner link | Content | T-1 (final agenda) |
| **Sponsors** | Sponsors (26 in 13 groups for BWS 2025) | Direct read + **canonical tier mapping** (group → tier) | Sales | T-7 |
| **Access programmes** | Wishlist Users; Pitch Room / Leadership Dialogue / Customer Success Showcase attendance | Wishlist direct read; **new "session attendance" check-in** per programme | Sales / Ops | T0 |
| **Social media** | Posts on LinkedIn, Instagram, Facebook, YouTube, X | **Post register** (URL, platform, posted_at, tagged partners). Phase 1: CSV upload of today's per-post export. Later: platform APIs | Social team | Each post logged when published |
| **Audio notes & photos** | Video team files | Media Center upload with **session / speaker tag** (drag-drop by session) | Video team | T0 evening |
| **Owned media** | ET BrandEquity articles, live stream / Studio, newsletter, YouTube | Web analytics + YouTube API; Email Marketing module | Editorial / Media | T+1 (partial) |
| **Feedback** | Attendee and partner survey | Portal form, sent automatically through Email Marketing at event close | Events | T0 close → T+1 (partial) |
| **History** | Previous editions of the same series | Series ID linking events (e.g. BWS 2024 → 2025 → 2026) | Platform | One-time setup |

### 3.2 Canonical data model (event-scoped, new tables)

```
series ─< event ─< session >─< speaker_appearance >─ person
                │     └─ owner_type, format, theme, partner_id, minutes
                ├─< registration >─ person ─ organisation (type, industry, size, logo)
                │     └─ status: registered | shortlisted | attended ; channel ; source raw
                ├─< sponsorship ─ organisation ; label (event) ; canonical_tier
                ├─< wishlist_entry (sponsorship, person/org) ─ outcome: invited | attended | met
                ├─< target (metric_id, value, stated_where)
                ├─< social_post (platform, url, posted_at, partner_tags) ─< metric_snapshot
                │                       (captured_at, window: pre | during | post, impressions, reach, engagements, views)
                ├─< media_asset (photo | audio | video, session, speaker, approved)
                │     └─< transcript ─< quote_candidate (text, speaker, ts, score, approved)
                ├─< survey_response (respondent_type: attendee | partner, rating, nps, comment)
                └─< report_version (as_of, metric values frozen) ─< export_log (who, when, sections)
```

- **`person` and `organisation` are deduplicated across events.** This makes year-on-year and repeat-attendee counts possible. It also lays the groundwork for a future sponsor-history / renewal view.
- **`metric_snapshot` is append-only.** T+1 and T+14 numbers both remain, and every export records which snapshot it used.

### 3.3 Processing and AI services

| Service | What it does | Method | Human in the loop |
|---|---|---|---|
| **Normaliser** | Fixes encoding ("DGM Ã¢â‚¬Å“" → "DGM –"), trims text, dedupes people (email) and organisations (name + domain) | Rules + fuzzy match | Merge suggestions under a threshold go to review |
| **Designation classifier** | Maps title to seniority (CXO / VP / Director / Manager / Other) and function (Marketing, Tech, Sales…); counts CMOs and CEOs | Rules first, LLM fallback, result cached per unique title | Override table; overrides are reused next time |
| **Organisation classifier** | Maps company to type (brand / agency / publisher / start-up / tech / other), industry and size band; fetches the logo for "brands in the room" | Company master + LLM fallback + cache | Override table |
| **Channel mapper** | Maps raw lead / visitor / conversion source (e.g. `nl_Mailer_newsletter_etcio_news_2026-03-13`) to a channel (newsletter, direct, partner, social, paid, referral) | Pattern rules | New patterns flagged |
| **Social window calculator** | Applies the agreed rule: pre = posted_at → event start, during = event days, post = after. Computes absolute figures and a **per-day normalised** multiplier | Deterministic | Formula shown on the page |
| **Transcription + quote extraction** | Audio → transcript → 3–5 quotable lines per session. Speaker identified from the agenda time slot and session tag | Speech-to-text + LLM ranking (quote must appear **verbatim** in the transcript) | Approver picks the final quotes |
| **Photo selector** | Tags photos (stage / audience / networking / partner activation / speaker) and proposes 8–12 with a spread of types. Speaker photos matched by tag | Vision model + upload tags | Approver confirms |
| **Narrative drafter** | One-line takeaway per section and captions, **written only from computed metric values** | LLM with the metrics JSON as the sole input; numbers in the text are re-checked against metrics | Editable before export |

### 3.4 Metrics layer
- **A registry of metric definitions.** Each has an ID, name, formula, source tables, base (n), unit, owner, and whether it can go in the PPT. Examples: `attendees_total`, `show_up_rate`, `cxo_share`, `unique_orgs`, `brands_present`, `wishlist_fulfilment_all`, `impressions_during`, `multiplier_per_day`, `yoy_attendees`.
- **Each report section is a set of metric IDs plus a drill-down query.** The page and the PPT render from the same computed values in a `report_version`.
- **Every metric carries its "as of" time and n,** and both are printed on the page and in the slide footnotes.

### 3.5 Quality and readiness

| Check | Type | Example | Effect |
|---|---|---|---|
| Readiness | Inputs present | Check-in < 50% of shortlisted, 0 media uploaded, 0 posts logged, targets missing, sessions untagged | Red on the checklist; the dependent section shows "not ready" |
| Consistency | Totals reconcile | Seniority buckets = attendees; channel totals = registrations | Blocks export |
| Plausibility | Out-of-range values | Show-up > 100%, multiplier > 20x, n < 30 for a percentage | Warning; approver acknowledges |
| Cross-source | Mismatch between sources | Speaker active on the website but not in the agenda; a figure that differs from the previous deck | Warning with both values shown |
| Unclassified | Coverage | > 5% of titles or companies unclassified | Warning + review queue |

### 3.6 Report page (internal UI)
- **Top bar:** event, "data as of", version, readiness score, **Generate PPT**.
- **Readiness checklist:** each input with its owner, status and a link to the module where it's fixed.
- **16 sections,** each showing:
  - the headline metric(s) with n
  - a chart
  - an AI takeaway line
  - a drill-down tab (lists and tables)
  - flags
  - an "include in PPT" toggle
- **Review queues:** classification overrides, quote picks, photo picks, dedupe merges.
- **Audit:** who changed or approved what, and every export.

### 3.7 PPT generator
- **Master template** built from Design → Top Banner: banner, logos, colours, fonts. There is one slide layout per section type:
  - stat tiles
  - bar / donut
  - logo wall
  - quote + photo
  - gallery
  - comparison
- **Assembly:**
  1. The selected sections are rendered with the frozen values from the `report_version`.
  2. Footnotes carry n, source and "as of".
  3. The output is PPTX and PDF.
- **Guards:** no attendee-level fields, and no section whose readiness is red (unless the approver overrides and the override is logged).
- **Export log:** records the version, sections included and who sent it. The T+14 v2 is a new export of a new version.

### 3.8 Orchestration

| When | Job |
|---|---|
| T-7 → T-1 | Daily readiness report to the owners: targets, agenda tags, sponsor tier mapping, post register |
| T0 (event day) | Hourly check-in and post-register sync; survey sent at close; reminder to the video team to upload |
| T0 + 2h after close | Full ingest → processing → metrics → **report version v1 (draft)** |
| T+1 07:00 | Notify the event lead: report ready, readiness score and open flags. Target: deck sent by noon |
| Daily to T+14 | Social / owned-media snapshots; survey responses |
| T+14 | Report version v2 → notify → regenerate PPT |

All jobs are idempotent and can be re-run on demand from the page.

### 3.9 Access and audit
- **Roles:** events team *editor* (review queues, captions), *approver* (event lead / IP owner; can export), *viewer* (sales, leadership).
- **Personal data stays inside the portal,** and exports are logged. This is in line with the registration consent and DPDP.

## 6. Success metrics
- **T+1 hit rate:** % of events where the deck is sent by noon on T+1. Target ≥ 90%.
- **Manual hours per deck:** baseline to be measured now; target −80%.
- **Numbers corrected after sending:** target 0.
- **Readiness score at T0 close:** target ≥ 85%. This is a leading indicator of whether the process is followed.
- **Downstream:** repeat-sponsorship rate for BWS partners, edition over edition.

## 7. Open decisions for engineering
1. **Portal stack and access.** The portal appears to be PHP (`etb2b_*.php`). Recommendation: add the UI module in the portal, with a separate processing / AI / PPT service (e.g. Python) that reads from the portal DB or API and writes to the new tables.
2. Does **check-in already write to the Attendees tab** on the day (badge scan / app), or is it done afterwards?
3. **Social API access:** does ET have app access for LinkedIn Pages, Meta Graph and YouTube Analytics for the BrandEquity handles?
4. **Company master:** reuse an existing ET organisation table if one exists, instead of building a new one.
